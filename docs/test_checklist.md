# 리모컨 펌웨어 검사 체크리스트

대상: 부팅 확인창 + 안전 홈 시퀀스 (Master v3.2.7+ / Remote posture-control 이후)
근거 스펙: [remote_firmware_spec.md](remote_firmware_spec.md)

---

## 검사 구분

| 구분 | 대상 | 시점 | 소요 |
|---|---|---|---|
| **A. 출하 검사** | 생산 전수 | 제품 1대마다 | 약 5분 |
| **B. 릴리스 검증** | 펌웨어 빌드 | 펌웨어 변경 시 1회 | 약 30분 |
| **C. 벤치 확인** | 마스터 담당자 | 최초 1회 / Master 버전 변경 시 | 약 30분 |

출하 검사는 **환자 없이, 매트리스 위에 사람이 올라가지 않은 상태**에서 수행한다.

> 시리얼 로그가 없어도 판정할 수 있도록 "육안 판정"을 기준으로 삼는다.
> 로그를 볼 수 있으면 "로그 확인" 열을 함께 본다. 로그는 115200 8N1.

---

## A. 출하 검사 (전수, 약 5분)

### A-1. 부팅 확인창 표시

| 항목 | 내용 |
|---|---|
| 준비 | 침대 메인 전원 OFF 상태에서 시작 |
| 절차 | 1. 메인 전원 인가<br>2. 침대가 스스로 움직이지 않는지 10초 관찰<br>3. 리모컨 화면이 꺼져 있는지 확인<br>4. 리모컨 전원키를 짧게 1회 누름 |
| **합격** | ☐ 전원 인가만으로 침대가 **전혀 움직이지 않는다**<br>☐ 전원키를 누르면 **"침대를 시작합니다"** 확인창이 뜬다<br>☐ 진행 바 10칸이 모두 **비어 있다** |
| **불합격 시** | 전원 인가 직후 침대가 움직임 → **즉시 중단.** 마스터 FW 버전 확인 (v3.2.4 미만 의심)<br>확인창 없이 홈 화면 → 리모컨 FW 구버전 |

### A-2. 3초 확인 → 홈 진행

| 항목 | 내용 |
|---|---|
| 절차 | 1. 확인창에서 **확인 키를 3초간 누른 채 유지**<br>2. 진행 바가 왼쪽부터 채워지는지 관찰<br>3. 3초 후 손을 뗌 |
| **합격** | ☐ 진행 바가 약 3초에 걸쳐 10칸 모두 채워진다<br>☐ 채워지는 즉시 **"초기화 중"** 화면으로 전환된다<br>☐ 침대가 홈 동작을 시작한다<br>☐ 홈 완료 후 **자동으로 대기 화면**으로 넘어간다 (수동 조작 불필요) |
| **불합격 시** | 진행 바가 안 채워짐 → 확인 키 배선/입력 확인<br>홈 완료 후에도 "초기화 중" 유지 → **Path B 미동작. 로그 필수 확인** |
| 로그 확인 | `[CONFIRM] accepted -> TX CMD2_STDBY`<br>`ACK: STDBY COMPLETE` 또는 `[PATH B] run_state 3->0` |

### A-3. 확인 도중 손 떼기 (진행 바 리셋)

| 항목 | 내용 |
|---|---|
| 준비 | A-2 이전 상태 (확인창 표시 중). A-2를 이미 했으면 메인 전원 재인가 |
| 절차 | 1. 확인 키를 약 1~2초만 누르고 손을 뗌 |
| **합격** | ☐ 진행 바가 **0칸으로 리셋**된다<br>☐ 확인창이 **그대로 유지**된다 (홈이 시작되지 않는다) |
| **불합격 시** | 홈이 시작됨 → **즉시 중단.** long-press 판정 로직 결함 |

### A-4. 확인창 중 전원키 숏클릭 무시 ★

> **가장 중요한 안전 항목.** 이걸 막지 못하면 확인 절차 자체가 무의미해진다.

| 항목 | 내용 |
|---|---|
| 준비 | 확인창 표시 중 |
| 절차 | 1. **전원키를 짧게 1회** 누름 |
| **합격** | ☐ 아무 일도 일어나지 않는다<br>☐ 확인창이 그대로 유지된다<br>☐ **침대가 움직이지 않는다** |
| **불합격 시** | 홈이 시작됨 → **즉시 출하 중단.** 확인 없이 침대가 동작함 |
| 로그 확인 | `KEY : POWER SHORT ignored (startup confirm active)` |

### A-5. 확인창 중 전원키 롱클릭 = 취소 + 전원 OFF

| 항목 | 내용 |
|---|---|
| 절차 | 1. 확인창에서 **전원키를 3초간** 누름 |
| **합격** | ☐ 리모컨 화면이 꺼진다<br>☐ 침대가 움직이지 않는다<br>☐ 전원키를 다시 짧게 누르면 **확인창이 다시 뜬다** |

### A-6. 통신 끊김 표시

| 항목 | 내용 |
|---|---|
| 준비 | 홈 완료 후 정상 대기 화면 |
| 절차 | 1. RS232 케이블을 뽑음<br>2. 약 6초 대기<br>3. 케이블을 다시 꽂음 |
| **합격** | ☐ 약 4~5초 후 **"연결 확인 중"** 화면이 뜬다<br>☐ 재연결 후 **원래 화면으로 자동 복원**된다 (모드가 홈으로 초기화되지 않는다) |
| 로그 확인 | `[LINK] LOST` → `[LINK] RESTORED` |

## B. 릴리스 검증 (펌웨어 변경 시 1회, 약 30분)

A 전체 + 아래 항목.

### B-1. 케어 모드 중 홈 → Path B ★

> 마스터가 돌봄케어 모드에서는 `ActionEcho`를 **보내지 않는다.**
> 이 경우 브로드캐스트 관찰(Path B)이 **유일한 완료 신호**다.
> 평소 사용에서는 절대 드러나지 않고, 케어 모드를 쓸 때만 터진다.

| 절차 | 1. 정상 대기 상태에서 **돌봄케어 모드** 실행<br>2. 케어 동작 중 **전원키를 짧게 1회** 누름<br>3. 홈이 진행되고 완료될 때까지 관찰 |
|---|---|
| **합격** | ☐ 홈 완료와 거의 동시에 대기 화면으로 전환된다 |
| **불합격** | "초기화 중" 화면이 **110초간 멈춰 있다가** 풀린다 → **Path B 미동작** |
| 로그 확인 | `[PATH B] run_state 3->0 -> homing done` 가 떠야 함 |

### B-2. 홈 진행 중 리모컨만 재부팅 → Path B

| 절차 | 1. 확인 후 홈이 진행되는 도중<br>2. **리모컨 전원만** 순간 차단 후 복구 (침대 메인 전원은 유지)<br>3. 리모컨 전원키를 짧게 누름 |
|---|---|
| **합격** | ☐ 확인창이 **뜨지 않는다** (이미 홈 진행 중이므로)<br>☐ "초기화 중" 스피너가 표시된다<br>☐ 홈 완료 시 **자동으로** 대기 화면 전환 |
| **불합격** | 홈이 끝났는데 스피너가 계속 돌면 Path B 미동작 |
| ⚠️ 로그 주의 | 이 경우 `[PATH B]` 로그는 **뜨지 않는다.** 리모컨이 `CMD2_STDBY`를 보낸 적이 없어 `stdby_in_progress`가 false이기 때문이다. **육안(화면 전환)으로만 판정한다.** |

### B-3. 마스터 재부팅 감지 (pending 0→1)

| 절차 | 1. 리모컨을 켜 둔 상태로 정상 대기<br>2. **마스터만** 재부팅 (또는 OTA) |
|---|---|
| **합격** | ☐ 수 초 내 **확인창이 자동으로 다시 뜬다**<br>☐ 침대가 스스로 움직이지 않는다 |
| 로그 확인 | `[PENDING] 0->1 (master reboot or watchdog) -> confirm required` |

### B-4. 리모컨만 재부팅, 침대 동작 중 (상태 복원)

| 절차 | 1. 마사지 등 모드 실행 중<br>2. **리모컨 전원만** 차단 후 복구<br>3. 전원키를 짧게 누름 |
|---|---|
| **합격** | ☐ 확인창이 뜨지 않는다<br>☐ 실행 중이던 모드 화면이 복원된다<br>☐ **침대 동작이 끊기지 않는다** (`CMD2_PWR_ON`이 나가지 않아야 함) |
| 비고 | 진행 시간(경과/잔여)은 payload에 없으므로 복원되지 않는다. **정상이다.** |

### B-5. GetBedStatus 실수신 (CMD1 오타 검출) ★

> `CMD1`을 `0x01`로 잘못 보내면 마스터가 조용히 무시하고 fallback으로 진입한다.
> **겉보기에는 정상 동작하므로 이 항목 없이는 검출할 수 없다.**

| 절차 | 1. 시리얼 로그를 켠 상태로 리모컨 부팅 |
|---|---|
| **합격** | ☐ `[BOOT] TX GetBedStatus (0x10,0xF1)` 로그가 뜬다<br>☐ 그 직후 BedStatus 응답이 수신된다 (`[RX] ESP32: ...`)<br>☐ `[BOOT] GetBedStatus no reply -> fallback` 이 **뜨지 않는다** |
| **불합격** | fallback 로그가 뜸 → CMD1 값 확인. 송신 바이트 7번째가 `10`이어야 한다 |
| 송신 바이트 | `FF 81 53 42 31 43 10 F1 00 [CRC_hi] [CRC_lo]` |

### B-6. 낙상 UI 비활성 확인

| 절차 | 마스터에서 낙상 경고(`0xA0`) 발생 |
|---|---|
| **합격** | ☐ 리모컨 화면이 **바뀌지 않는다** (현재 낙상 기능 미동작, 의도된 상태)<br>☐ 로그에 `*** FALL ALERT (UI disabled) ***` |
| 비고 | 낙상 기능 활성화 시 `drive/protocol.h`의 `FALL_ALERT_UI_ENABLED`를 `1`로 변경 후 재검사 |

## C. 벤치 확인 (마스터 담당자, 최초 1회)

**전부 환자 없이, 매트리스 위에 사람이 없는 상태에서 수행한다.**

| # | 항목 | 절차 | 합격 기준 |
|---|---|---|---|
| C-1 ★ | 구버전 마스터가 `0xF1`을 안전하게 무시하는가 | Master v3.2.3 + 신규 리모컨 연결, 리모컨 부팅 | ☐ 마스터 로그에 `Unknown Action: 0xF1`<br>☐ **모터가 전혀 움직이지 않는다** |
| C-2 | 구버전 마스터가 `DataLen ≥ 10`을 보내는가 | Master v3.2.3의 BedStatus 패킷 덤프 | ☐ DataLen이 10 이상. 미달이면 리모컨이 패킷 전체를 드롭해 fallback도 성립하지 않음 |
| C-3 | `ActionEcho`가 홈 완료 시점에만 발송되는가 | 홈 실행 중 마스터 로그 관찰 | ☐ `Sent STDBY ACK to remote control` 이 홈 **완료 시점에만** 1회 |
| C-4 | 케어 모드 중 홈 완료 시 리모컨이 복귀하는가 | B-1과 동일 (마스터 로그 병행) | ☐ 마스터가 ActionEcho를 안 보내는 것을 확인<br>☐ 리모컨은 Path B로 복귀 |
| C-5 | watchdog 복구 | 홈 진행 중 driver stall 유발, 90초 초과 | ☐ 마스터가 `startup_pending=1` 복구 브로드캐스트<br>☐ 리모컨에 확인창 재표시 (최대 2초 내)<br>☐ 리모컨이 일반 UI로 들어가지 **않는다** |

> **C-1을 통과하기 전에는 구버전 마스터를 실기(환자용 침대)에 연결하지 말 것.**
> `CMD1=0x10`은 모든 버전이 인식하는 유효 명령이라, 이 패킷은 구버전 마스터의 CMD2 분기까지 도달한다. unknown CMD2의 처리가 no-op이라는 보장이 없다.

## 롤아웃 주의

**리모컨을 먼저 업그레이드한다.**

신 마스터(v3.2.7) + 구 리모컨 조합에서는:

1. 전원키 1번째 누름 → `CMD2_PWR_ON` 송신 → 마스터가 거부 → **5초간 무반응** (사용자는 고장으로 인식)
2. 전원키 2번째 누름 → `CMD2_STDBY` 송신 → **확인창 없이 홈 시작** (안전 절차 우회)

가용성과 안전 양쪽 모두 문제가 된다. 이 조합이 필드에 나가서는 안 된다.
